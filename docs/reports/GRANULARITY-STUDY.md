# Claim 粒度深挖（P0.3 实验）

> 问题：claim 粒度"太细"（一句一原子事实、30% 脱离上下文读不懂、检索差）与"太粗"（匹配难、成本高、丢精度）之间怎么取？
> 方法：对 8 篇文档（4 篇文章 + 4 个视频）分别生成 **L1 原子 / L2 自足命题 / L3 段落块** 三种粒度，用 Jev 度量自足率与检索命中，并记录抽取成本。

---

## 1. 三层定义

| 层 | 定义 | 例子 |
|---|---|---|
| **L1 原子事实** | 一句一个最小事实，允许指代、不要求脱离上下文 | 「Apple 建议用户更新到最新软件。」 |
| **L2 自足命题** | 每条自带主语、范围/条件/时点；同一断言的相关细节合并；脱离原文可理解 | 「Apple 发布的 macOS 27.2.1 更新修复 eMudhra 证书漏洞，并建议用户升级；运行 macOS 26 / 15 的机器分别有 26.7.3 / 15.8.3 更新。」 |
| **L3 段落块** | 120–250 字的连贯段落，读起来像短文，保留数字与结论 | 「macOS 27.2.1 修复了命令行工具中的 eMudhra 证书漏洞…Apple 曾在 10 月于 Safari/Mail 中阻止该证书…」 |

## 2. 结果（8 篇聚合）

| 层级 | 单元/篇 | 平均字数 | **自足率** | **检索命中率** | 抽取 token/篇 |
|---|---|---|---|---|---|
| L1 原子 | 10.5 | 30.5 | **0.19** | **0.25** | 5,444 |
| **L2 命题** | 7.3 | 91.6 | **0.49** | **0.50** | 5,860 |
| L3 段落 | 3.8 | 202.5 | 0.07\* | **0.75** | 3,552 |

\* L3 的自足率数字不可直接对比：判据问的是"读者不看原文能否完全理解"，长段落里常带"该漏洞/该问题"这类回指，被判为需要原文；但它作为**阅读材料**是可读的（例子见上）。

**逐篇差异很大**，例如 macOS 那篇：L1 自足 0.25 → L2 自足 **0.88** → L3 0.25。说明"命题化改写"对技术类文章收益最大。

## 3. 怎么读这组数

1. **L2 是记忆/检索的甜点**：自足率是 L1 的 2.6 倍、检索命中是 2 倍，而抽取成本只 +7.6%，行数还少 30%。
2. **L1 不是没用**：它是判重/冲突/溯源的最佳层（原子性最好、可逐字对上原文）。但**不能直接拿来给人看或做检索**。
3. **L3 适合阅读**：检索命中最高（0.75）是因为长块里包含答案原文；但块太长，判重与冲突几乎无法在块级做。
4. 三者不是替代关系，而是**同一条记忆的三个视图**。

## 4. 建议的结构

```
block（段落/成稿）        ← 阅读单位（用户要读的东西）
  └ proposition（自足命题） ← 记忆/检索单位（带上下文信封）
      └ fact（原子事实）     ← 判重/冲突/溯源单位（逐字证据）
```

`proposition` 本质是"fact + 上下文信封"：

| 字段 | 作用 |
|---|---|
| `text` | 自足陈述（显式主语，无指代） |
| `subject` / `predicate` / `object` | 类型化三元组（可空） |
| `scope` / `conditions` | 适用范围与条件（硬件/地区/口径） |
| `as_of` | 该命题成立/被观察到的时间 |
| `block_id` | 回指原文段落（阅读入口） |
| `fact_ids` | 组成它的原子事实（溯源、判重） |
| `self_sufficient` | 是否通过自足性校验 |

## 5. 迁移路径（不重抽全库）

1. 现有 5,618 条 claim 保留为 **fact 层**（判重/冲突已在其上工作）。
2. 对自足性不达标的 claim（按 L1 自足率估计约 30–50%）做一次"命题化改写"，生成 proposition；
3. 新抽取直接双产出：`fact`（细）+ `proposition`（自足），成本约 +8%；
4. 阅读层按 block 生成（或复用 `article.md` 式成稿）。

## 6. 局限（必须说明）

- 样本只有 8 篇；2 个视频的 L2/L3 抽取失败（ASR 无标点导致 JSON 结构异常），已从聚合里体现为 0 单元，会拉低 L2 均值。
- 自足率判据对长块偏严（见上），L3 数字应与 L2 分开解读。
- 检索测试用"trigram 相似度 top1 + Jev 判定是否回答问题"，不是真正的语义检索；换成 embedding 后 L2 的优势可能更明显。
- 抽取与判定均由 LLM 完成，没有人工金标。

## 7. 下一步

1. 样本扩到 50 篇（含 20 个视频），重新标定三层指标；
2. 定义 `proposition` 的 envelope schema 并落库；
3. 对现有 claim 做"命题化补全"实验，测量补全后的自足率与检索提升；
4. 用 embedding 替代 trigram 做检索对照。

# 附：50 篇扩充版（P0.4 复测）

样本：25 篇文章（正文 ≥1,500 字）+ 25 个视频（转写 ≥2,000 字），共 50 篇，每篇取前 3,500 字。

| 层级 | 单元/篇 | 平均字数 | 检索命中率 | 说明 |
|---|---|---|---|---|
| L1 原子 | 12.0 | 33.5 | **0.23** | 文章 0.10 / 视频 0.36 |
| L2 命题 | 9.8 | 80.2 | **0.69** | 文章 0.71 / 视频 0.68 |
| L3 段落 | 4.4 | 190.9 | **0.76** | 文章 0.70 / 视频 0.82 |

**结论与 8 篇版一致**：L1 的检索命中只有 L2 的 1/3；L2 用少 18% 的单元、多 2.4 倍的字数换到 3 倍的检索命中；L3 检索最好但过粗（4.4 块/篇），无法用于判重与冲突。

**方法学修正（重要）**：50 篇版的自足率用了"分层判据"（每层标准不同），跨层不可比（L1 0.37 / L2 0.32 / L3 0.22），**不应据此下结论**；8 篇版用统一判据（L1 0.19 / L2 0.49 / L3 0.07）才是可比的。检索率两版口径一致，可以比较。

**成本**：50 篇 × 3 层抽取 = 210 次调用 / 84.1 万 token；Jev 自足+检索判定 363 次 / $0.103。
