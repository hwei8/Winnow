# P0.2 打磨检查：Claim 能不能当"记忆基本单位"？

> 问题背景：用户明确否决"claim 信息流"，并要求先验证 **claim 作为记忆基本单位是否可行**。
> 方法：接入真实新闻流（HN / NYT / 知乎 / 36氪，共 264 条），对五个维度逐项实测。
> 结论：**技术上可行，但有三个前提条件；且 claim 只能当"记忆/索引单位"，不能当"阅读单位"。**

---

## 0. 数据与源

| 源 | 条目 | 内容形态 | 备注 |
|---|---|---|---|
| Hacker News | 100 | 标题 + 外链 | 外链正文抓取成功率 **87%**（52/60，p50 8,163 字） |
| The New York Times | 100 | 标题 + 摘要（~148 字） | 正文 403 反爬，只能验证到摘要层 |
| 知乎 | 44 | 问题描述（平均 1,188 字） | 官方 RSS 不可用，走公共 RSSHub 镜像热榜 |
| 36氪 | 20 | 快讯（~103 字） | 官方 feed 返回拦截页，走 RSSHub 镜像 |

合计 **264 条真实条目**，抽取 **1,840 条 claim**（引用接受率 97.7%，平均置信度 0.895，类型化率 98%）。

## 1. 重复性

**事件级**（候选对 → LLM 判定"是否同一事件" → 并查集）：

| 指标 | 值 |
|---|---|
| 条目 | 264 |
| 候选对 | 200（词面/实体/数字三路召回） |
| 判定为同一事件 | 6 对（转化率 3%） |
| 多条目事件簇 | **4 个（9 条）** |
| 重复条目率 | **1.9%** |
| **跨源同事件** | **0** |

簇的样子：

- NYT：克拉科夫枪击案 **3 篇**（"政治风波""波兰人追问""嫌疑人死亡"）
- HN：`Val Town is winding down` **2 条**（重复投稿）
- HN：`Gemini 4 Carbon` **2 条**（发布/滚动上线）
- NYT：David Walliams 性骚扰指控 **2 篇**

**claim 级**（同一事件簇内，跨条目 claim 对）：**108 对 → 0 对"同一事实"**。

**判读**：
- 这批源的冗余**主要发生在"同一媒体对同一事件的多篇报道"（事件级）**，而不是 claim 级——因为 RSS 只给摘要，每篇摘要讲的角度不同，主张天然互补。
- **跨源同事件为 0**：四个源内容域差异大（HN 技术 / NYT 国际 / 知乎社会 / 36氪商业），264 条样本下几乎不重叠。要测跨源重复，必须接同域的多个源（如多家科技媒体）。
- 之前视频语料（142 视频 → 141 事件）也是同样结论。**两批数据都说明：重复性问题在"事件/报道"层，不在"句子"层。**

## 2. 可验证性（claim 的强项）

| 指标 | 值 |
|---|---|
| 抽取时的硬门槛 | quote 必须在原文出现，否则**直接丢弃** |
| 引用接受率 | **97.7%**（接受 1,840 / 丢弃 43） |
| 字符偏移精确命中 | **97.8%**（391 / 400 抽样逐字相等） |
| LLM 复核（30 条抽样） | supported 22 / partial 8 / **unsupported 0** |

**判读**：**claim 的可验证性成立且强**——这是它作为记忆单位最大的优势（视频源 30 条抽样也是 0 幻觉）。但前提是"拿得到原文"：
- RSS 摘要 → 只能验证到摘要层，信息量低；
- 正文抓取 → HN 外链成功率 87%，NYT 403、36氪官方 feed 被拦，需要专门的抓取/渲染管线。

## 3. 增删改查（CRUD）

用最小字段（`status` + `superseded_by` + `asserted_at`）跑通：

| 操作 | 结果 |
|---|---|
| Create | ✅ 写入后可查 |
| Read（by id / by subject / FTS / entity） | ✅ |
| Update（新 claim 取代旧 claim） | ✅ `superseded_by` 链 + active 视图只剩新值 + 历史视图两条都在 |
| Delete（软删 `retracted`） | ✅ |
| Delete（硬删） | ✅ 但**需手动清证据，无外键级联** |

**缺口**：
- 没有显式 revision 表 —— 历史靠"同 subject+predicate 的 claim 链"表达；
- 删除没有级联；
- 状态值是自由文本，没有枚举约束（建议 `active | superseded | retracted | unverified | meta`）。

**判读**：**claim 能支撑基本 CRUD**。"改"走"新增 + 旧条目标 superseded"而不是原地改，这对记忆系统是正确行为（保留历史）。

## 4. 时效性

| 指标 | 值 |
|---|---|
| claim 总数（新闻） | 1,840 |
| `asserted_at` 覆盖（= 来源发布时间） | **1,840 / 1,840（100%，回填）** |
| `source_tier` 覆盖 | 100% |
| `world_from`（事实何时成立） | **0** |
| 30 天前的 claim 仍 `active` | 39 条 |
| "最近 7 天"查询 | ✅ 可用（按发布时间） |

**判读**：
- "什么时候说的"有了（asserted_at），"什么时候发生的"没有（world_from 全空）；系统目前**无法区分"旧事实已过期"和"旧事实仍然成立"**。
- 需要：抽取时补 `world_from`（原文有明确时间才填）、加"复核周期"字段、过期 claim 自动降级为 `stale` 而不是继续 active。

## 5. 新旧冲突

| 指标 | 值 |
|---|---|
| 候选冲突（同 subject+predicate、不同 object） | 20 对（全库共 92 对） |
| 严格判定为**真冲突** | **0** |
| 误报率 | **100%** |

误报示例（被判"不是冲突"是对的）：

```
主体「赞特」谓词「买下」：1995 年买荷兰碉堡 vs 2013 年买德国堡垒 → 不同对象，不冲突
主体「AI编程」谓词「has_problem」：第一个问题是错误假设 vs 第三个问题是附带伤害 → 同一主语不同属性
主体「Shadow服务器」谓词「has」：有 64GB 内存 vs 没有本地存储 → 不同属性
```

**判读：冲突检测的瓶颈不在判定逻辑，而在"类型化粒度"。**
- 谓词太泛（`has` / `equals` / `买下` / `研发`），同一主语的不同属性被当成同一属性；
- 对象没有类型与单位（"64GB 内存" vs "没有本地存储"不可比）；
- 必须引入：**谓词注册表 + 对象类型/单位归一 + 值可比性判断**，否则冲突检测会持续误报。

## 6. 结论：claim 能否当记忆基本单位？

**能，但有三个前提；且定位必须收窄。**

| 维度 | 判定 | 前提 |
|---|---|---|
| 可验证性 | ✅ 强（0 幻觉、97.7% 引用硬校验） | 拿得到原文 |
| CRUD | ✅ 基本可用 | 版本语义（superseded 链）、软删、级联 |
| 时效性 | ⚠️ 缺一半 | 双时间轴（world_from/to）+ 复核周期 |
| 新旧冲突 | ❌ 目前不可用 | 谓词注册表 + 对象类型/单位归一 |
| 重复性 | ⚠️ 层次判断 | 冗余在"事件/报道"层，不在句子层；claim 级去重只在同域多源+正文时才有意义 |

**定位建议（已记入 DECISIONS D15）**：

```
阅读单位 = 文章 / 事件成稿（连贯内容，用户要读的东西）
记忆单位 = claim（索引、判新、溯源、冲突检测）
内容单位 ≠ 记忆单位
```

如果后续验证发现 claim 颗粒度无法稳定支撑（例如谓词始终无法收敛），退路是：**以段落为记忆单位、claim 只做检索索引**——这样"可验证性"仍在，但"冲突检测"要改成段落级比对。

## 7. 本次发现并修掉的工程问题

1. **Story 归属被覆盖**：并查集生成的簇与"单条兜底组"重复包含同一 item，后写入的单条 story 把簇的 claim 归属覆盖掉（表现为"有簇但簇内 0 claim"）。修复：用索引集合去重。
2. **时效字段没落库**：抽取 prompt 给了 `asserted_at`，但写库时漏写。已修 + 用"来源发布时间"回填（语义正确，无需重跑）。
3. **长 ID 传参失败**：把 24 位不透明 id 塞给模型做聚类，模型会篡改字符串导致匹配失败（一度得到"0 个多条目事件"的错误结论）。改用序号传参。
4. **判定类调用必须带对照**：冲突判定第一版宽松（判 12 条"真冲突"），收紧后变 0 条；如果不抽查，会把误报当结论。这次没有写库（`APPLY=1` 才落库），避免污染数据。
