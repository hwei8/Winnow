# 主动搜索 → 唯一 Claim 库 → Story 覆盖度（P0.4 实验）

> 用户的假设：不靠订阅源，而是**主动搜索**同一事件的多篇报道，抽取、去重，能否得到"唯一、不重复、且覆盖完整 Story"的 claim 库？
> 测试对象：2026-11 英伟达 CEO 黄仁勋婚外情/中国间谍指控事件（真实、多源、跨语言）。

## 1. 管线

```
web_search（4 组查询）
  → 14 个 URL（BBC / CNBC / Anadolu / 香港01 / TVBS / TOI / Tribune / CNBC-TV18 / Economic Times / Excelsior / NOS / Standard×2）
  → 抓正文（36_search_ingest）71,357 字
  → 抽 claim + 逐字引用硬校验（37_search_claims）240 条，接受率 98%
  → 候选对 + Jev 判定去重（38_search_dedupe_coverage）86 对 → 13 对重复
  → 生成 24 个"完整 story 应覆盖的事实点"（facets）→ Jev 三档判定覆盖率
```

## 2. 结果

| 指标 | 值 |
|---|---|
| 源文章 | 14 篇（实际抽出 claim 的 10 篇；4 篇过短/无可用正文） |
| 总字数 | 71,357 |
| 抽取 claim | **240 条** |
| 去重后唯一 claim | **228 条** |
| 重复率 | **5%（13 对，8 组）** |
| Story facets | 24 |
| 被 claim 库覆盖 | **20 / 24 = 83.3%** |
| 完全覆盖（无缺失要素） | 14 / 24 = 58.3% |

**重复率极低**——因为不同媒体对同一事件的报道角度不同，真正的逐字事实重复集中在少数"通稿式"表述上。被合并的典型组：

```
「Nvidia 表示没有理由认为公司机密或国家安全受到损害。」×5 个变体（5 家媒体）
「中国周一否认这些指控。」×2
「特朗普周一表示，他对涉及 Jensen Huang 的指控感到惊讶。」×3
「黄仁勋说出『我的枪太强大』等言论。」×2（中英文各一）
```

## 3. 未覆盖的 4 个 facet（关键发现）

| 缺失 facet | 原因猜测 |
|---|---|
| 2024-06-07 黄仁勋与 Alice Huang 在台北同框的照片 | 单源细节 + 抽取上限（每篇最多 20 条） |
| Alice Huang 在台北某餐厅参加黄仁勋主持的晚宴 | 单源细节 |
| 相关视频「重新浮出」并与性丑闻关联 | 视频证据，正文里只有描述 |
| 华尔街芯片股稳健上涨、看涨情绪未被打垮 | 评论性/行情类，被抽取当成"观点"丢弃 |

**结论：缺失主要来自"抽取覆盖"，不是"去重过度"。** 去重只删了 5%，而 4 个缺口里有 3 个是单源细节、1 个是视觉/视频证据。

## 4. 与"唯一且完全不重复 + 完整覆盖"的距离

| 目标 | 现状 | 差距 |
|---|---|---|
| 唯一（无重复） | 95% | 候选召回有限，可能仍有漏网的跨语言改写（"中国否认" vs "北京否认"） |
| 完整覆盖 Story | 83%（完全覆盖 58%） | 抽取上限、单源细节、视频/图片证据未处理 |
| 可验证 | 98% 引用逐字命中 | ✅ |
| 可追溯 | 每条 claim 有 char offset + item | ✅ |

## 5. 这个实验说明的管线设计

要真正做到"唯一 + 完整"，需要三步闭环：

1. **覆盖驱动的补采**：先用 facets 检查覆盖率，对未覆盖的 facet **自动发起二次搜索/抓取**（而不是只采一轮）。
2. **按块抽取、不设总量上限**：长文分段抽（每段独立），避免 20 条上限吃掉细节；目前 14 篇里最长 9,361 字。
3. **视觉证据单独建层**：视频/图片用 OCR/关键帧 + 描述，作为 claim 的 evidence 而不是正文抽取的副产品。
