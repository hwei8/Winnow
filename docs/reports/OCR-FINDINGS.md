# OCR 纠错抽样实验（P0.2 预研）

> 问题：`Summary` 里有 42,001 张截图帧，且画面底部常有烧录字幕。**能不能用它们纠正 ASR 的术语/数字错误？**
> 结论：**能读出字幕，但不能直接对齐**。OCR 是"候选增强路径"，不是"ASR 修复器"。

---

## 1. 实验设计

- 抽样 21 个视频（ASR 质量分三档：最差 7 / 中位 7 / 最好 7）
- 每视频均匀取 6 帧，共 **126 帧**
- 用视觉模型只转录"画面底部字幕"（要求无字幕输出 `NO_SUBTITLE`）
- 与同一帧对应 ASR 段比较；由于字幕常跨多段且与帧有时间差，用 **±12 段的滑动窗口**取最优对齐

成本：**124,973 tokens / 126 帧 ≈ 992 tokens/帧**（约 $0.0002/帧）。

## 2. 结果

| 指标 | 值 |
|---|---|
| OCR 调用成功 | 126 / 126 |
| 检出"字幕" | 100 / 126（79.4%） |
| 与 ASR 对齐 ≥0.8（LCS 比率） | **22 / 100（22%）** |
| 对齐 ≥0.6 | 34% |
| 对齐 <0.5（不可用） | **59%** |

按 ASR 质量分档（越差的视频反而对齐越好）：

| 组 | n | 对齐≥0.8 | 平均最优相似度 |
|---|---|---|---|
| ASR 最差 | 27 | **12** | 0.558 |
| ASR 中位 | 35 | 7 | 0.439 |
| ASR 最好 | 38 | 3 | 0.243 |

## 3. 读对了字幕的证据（确实能纠错）

| ASR | OCR（画面字幕） | 说明 |
|---|---|---|
| `这是当前主流的扩散模型和VA2模型的图像生成过程` | `这是当前主流的扩散模型和VAR模型的图像生成过程` | **VAR 模型被纠正** |
| `2026年,Harness Engineering成为` | `2026年，Harness Engineering 成为 AI 工程领域最火热的话题之一。` | 补全整句 |
| `继续需要CD密药` | `攻击者窃取 CI/CD 密钥，篡改构建脚本，在 minify 或打包阶段植入恶意 payload` | **CI/CD 密钥**被纠正 |
| `这句像是把餐厅改成了合犯算买机` | `这就像把餐厅改成了盒饭贩卖机，没有服务员，没有厨师，没有厨房` | 整句可读 |
| `单帧精确匹配` | `应该也不用进行对比了` | 与 ASR 完全一致（对照组） |

## 4. 为什么 59% 对不上（这是关键）

1. **字幕与帧有时间差**：字幕先出现、语音后到；按"帧=段起点"对齐天然错位。
2. **字幕跨度 ≠ ASR 段跨度**：ASR 段 2–4 秒一句，字幕往往 10–15 秒一行；即使 ±12 段滑动窗口，匹配也常常只覆盖一部分。
3. **模型会读画面上别的文字**：把 `防走丢`、`防眩光`、产品标签当成"字幕"输出——`NO_SUBTITLE` 约束并不总能挡住。
4. **部分视频本来就没有烧录字幕**（字幕是平台外挂的），这些帧只剩闲聊/水印文字。

## 5. 结论与建议

**不要**把 OCR 当成"自动修 ASR"的现成方案：它需要一条独立的字幕抽取管线。

建议的 P0.2 做法（如果要做）：

1. **裁字幕区域**（底部 20% 条带）再送 OCR，减少画面文字干扰，成本也会大降。
2. **先做字幕存在性判别**（分类/规则：该条带是否有文字），再 OCR。
3. **对齐单独做**：把 OCR 文本当作独立语料，用全局模糊匹配（或 DTW）对齐到转写时间轴，而不是"帧 ↔ 段"直接配对。
4. 只对**低 asr_quality 的视频**启用（这批恰是技术类、术语错得最多、且对齐率最高的一档：12/27）。

**当前价值定位**：帧作为"claim 的视觉证据 + 人工跳转核验"是成立的（已验证 69.5% 的 claim 能配帧）；但"自动 OCR 纠错"要等上面这条管线做出来才算落地。
