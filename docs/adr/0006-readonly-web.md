# ADR 0006 — 只读 SSR：浏览不会改数据

- 状态：已采纳
- 相关：`src/web/`、docs/web.md

## 背景

Web 端既要能读（无限流、详情、搜索），也要能写（捕获、标注、追平）。把两者混在一个查询层里，容易出现"打开页面顺手写了一条 `story_update`"的意外。

## 决策

- 查询层（`web/queries/*`）**只读**，只发 `SELECT`；
- 所有写入集中在 `web/write.mjs`，由 `POST /api/*` 触发；
- 渲染用 SSR + 纯函数模板，没有前端框架、没有构建步骤；
- 交互用少量原生 JS（`public/app.js`），只做局部增强。

## 后果

- ✅ 浏览路径不可能意外改库；
- ✅ 首屏快、可 grep、部署零构建；
- ✅ 查询层可以对着空库跑测试；
- ⚠️ 复杂交互要手写 JS（可接受：页面少）；
- ⚠️ 无登录，必须靠反代/隧道兜住鉴权。

## 备选

| 方案 | 为什么不选 |
|---|---|
| SPA + API | 为一个个人工具引入构建链与状态管理，收益低 |
| 服务端框架（Express/Fastify） | 路由只有十几条，标准库足够 |
| GraphQL | 过度设计 |
